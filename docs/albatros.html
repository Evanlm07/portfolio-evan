Déploiement du mini-SI de la PME Albatros

Déploiement complet du système d’information d’une PME fictive : annuaire, proxy, inventaire, supervision, journaux et sauvegardes.

1. Annuaire et GPO (SRV-DC01)

Scripts PowerShell lancés dans l’ordre : préparation (IP fixe, rôles AD DS et DNS), promotion en contrôleur de domaine, puis création de l’annuaire : OU ALBATROS (Utilisateurs, Ordinateurs, Groupes), comptes ibra, pao, sam, groupe GG-IT et GPO GPO-Proxy-Standard.

# GPO proxy liée à l'OU Ordinateurs
New-GPLink -Name 'GPO-Proxy-Standard' -Target "OU=Ordinateurs,OU=ALBATROS,DC=albatros,DC=local"
$is = 'HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings'
Set-GPRegistryValue -Name 'GPO-Proxy-Standard' -Key $is -ValueName ProxyEnable -Type DWord  -Value 1
Set-GPRegistryValue -Name 'GPO-Proxy-Standard' -Key $is -ValueName ProxyServer -Type String -Value '192.168.205.20:3128'
# empêcher l'utilisateur de modifier le proxy
Set-GPRegistryValue -Name 'GPO-Proxy-Standard' -Key 'HKLM\Software\Policies\Microsoft\Internet Explorer\Control Panel' -ValueName Proxy -Type DWord -Value 1
# bouclage : la partie Utilisateur s'applique via l'OU des ordinateurs
Set-GPRegistryValue -Name 'GPO-Proxy-Standard' -Key 'HKLM\Software\Policies\Microsoft\Windows\System' -ValueName UserPolicyMode -Type DWord -Value 1

2. Services Linux (SRV-LNX01)

Un script install.sh fixe l’adresse IP (netplan), installe Docker et restic, puis démarre chaque pile avec docker compose up -d.

# squid.conf : seuls le réseau local et les réseaux Docker passent
acl localnet       src 192.168.205.0/24
acl docker_bridges src 172.16.0.0/12
http_access allow localnet
http_access allow docker_bridges
http_access deny all

3. Sauvegarde et restauration (PRA)

restic sauvegarde la base et les fichiers de GLPI dans un bucket MinIO, chaque nuit à 2 h (cron). Rétention : 7 sauvegardes quotidiennes et 4 hebdomadaires.

# restic-glpi.sh (extrait)
docker compose -f "$STACK/docker-compose.yml" stop
trap 'docker compose -f "$STACK/docker-compose.yml" start' EXIT
restic backup --tag glpi /var/lib/docker/volumes/glpi_dbdata/_data /var/lib/docker/volumes/glpi_glpidata/_data
restic forget --tag glpi --keep-daily 7 --keep-weekly 4 --prune

La restauration est testée : un script simule une corruption de la base GLPI (incident n°2), puis restore-glpi.sh restaure le dernier instantané et mesure le temps de remise en service (RTO).

# restore-glpi.sh (extrait)
T0=$(date +%s)
restic restore latest --tag glpi --target /
docker compose -f "$STACK/docker-compose.yml" start
until curl -fsS -o /dev/null http://127.0.0.1:8080/; do sleep 2; done
echo "GLPI de nouveau en ligne. RTO mesuré : $(( $(date +%s) - T0 )) s"
À compléterAjoute le RTO mesuré, les captures (GPMC, GLPI, tableau de bord Zabbix, Grafana) et les fiches des 3 incidents.

Écarts par rapport à l’énoncé

  • Réglages du proxy posés en valeurs de registre, avec bouclage de GPO.
  • Agent Zabbix ouvert aussi au réseau Docker (172.16.0.0/12), sinon le serveur en conteneur est refusé.
  • Sauvegardes planifiées par cron système.
